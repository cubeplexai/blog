2026 年 9 月 28 日，Manus 2.0 发布，将 Cloud Computer 纳入这一版本，Agent 有了可以长期使用的工作环境。此前，Manus 已经能在远程 Sandbox 中运行代码和处理文件，也能操作浏览器，但临时环境会在任务结束后被回收。Cloud Computer 保留文件和软件配置，让后续任务接着使用，程序也能持续运行。为 Agent 提供持久的工作环境，是近期 Agent 产品演进的一个主要方向。

执行环境能保留多久，值得关注。普通 Sandbox 在任务结束后会被关闭，报告、表格等交付结果保存在聊天记录里，底下的工作环境不再保留。Cloud Computer 是专属的持久化云端虚拟机，文件和已安装工具可以跨会话使用，程序也能持续运行。[Manus Cloud Computer 帮助说明](https://help.manus.im/en/articles/15392111-what-is-the-cloud-computer)

## 临时 Sandbox 和持久化云电脑

临时 Sandbox 适合有明确结束点的工作。分析一份数据、运行一个脚本，或者生成一份文档，完成后交付结果，执行环境随后可以回收。

持续开发的项目需要保留更多东西。下次继续修改代码时，依赖已经装好，数据还在原来的目录，之前配置的数据库也能接着用。Cloud Computer 会保留这些文件和软件配置。服务进程可以跨会话运行，用户结束一次对话，机器人或服务器仍然在线。

文件留存和程序持续运行分别解决了两类麻烦。前者省去重复上传的工作，也省去再次安装和配置的工作；后者支持机器人、游戏服务器等需要一直响应请求的服务。对这类项目，交付一份代码之后，还需要长期保留并维护运行它的环境。

Manus 仍然保留普通 Sandbox。官方说明中，每个任务先在临时 Sandbox 中开始，再根据任务需求决定是否使用 Cloud Computer。持久化云电脑适用于需要延续环境或常驻服务的工作，不要求每个一次性任务都长期占用一台机器。[Cloud Computer 产品说明](https://manus.im/blog/manus-cloud-computer)

## 数据库跨周积累，报告用上历史数据

Manus 的 Cloud Computer 产品页给出了一个周度销售分析的例子。用户建立 MySQL 数据库，每周上传新的 CSV，由程序更新数据并生成趋势报告。后面的报告可以使用此前积累的数据，数据库也不需要随每次任务重新建立。

这类工作需要保留的不只有最后导出的表格。数据库中的历史记录和处理数据的程序都要留着，运行配置也要保留，下周才能继续执行。聊天记录里存有上周的报告，不能替代仍然可用的数据库。

已经安装的软件也有类似需求。Manus 列举了 Metabase、Home Assistant 等开源工具，以及命令行开发工具。安装和配置完成后，用户可以继续使用它们，让 Agent 在原来的环境中修改或处理新的文件。每次重新创建临时 Sandbox，都要再次准备这些软件和配置。[Cloud Computer 产品说明](https://manus.im/blog/manus-cloud-computer)

## 对话结束后，机器人和采集程序继续运行

帮助说明还列举了全天在线的 Discord 机器人，以及每小时执行一次的网页采集程序。机器人需要接收用户消息，采集程序则需要继续按计划执行。用户结束当前对话后，这些程序仍然有工作要做。[Cloud Computer 帮助说明](https://help.manus.im/en/articles/15392111-what-is-the-cloud-computer)

持续保存环境和持续运行程序，各有具体用途。销售数据要跨周积累，安装过的工具要在后续任务中使用；机器人需要保持服务可用，采集程序则要在指定时间运行。临时 Sandbox 适合执行完就交付结果的任务，Cloud Computer 为这些后续工作保留了文件和软件配置，也保留了运行环境。

Manus 2.0 的多人游戏沿用了同样的需求。Agent 生成游戏之后，联机服务器还要持续响应玩家。用户在 Game Dev 中选择多人联机并购买 Cloud Computer，Manus 负责后续配置。游戏生成后的托管也能在产品内完成，用户可以继续修改游戏，同时保留运行中的服务。

## 团队继续使用 Agent 时留下什么

Cloud Computer 所强调的环境延续，同样适用于团队日常使用 Agent。代码和素材经常需要隔天继续处理，后续任务也可能使用已经安装的软件。执行环境保留下来，成员就能接着工作。多人协作时，还需要确定哪些文件由团队共享，哪些只属于个人任务。

CubePlex 是面向团队的 Agent 工作平台，成员可以在同一个 Workspace 中使用共享的 Agent、知识和工具。

CubePlex 在设计之初就确定了为 Agent 提供持久化的工作环境，通过 Sandbox 保存工作文件并执行任务。成员的一对一对话默认使用个人的 Workspace Sandbox，新建对话仍可使用其中的工作文件。群聊会话和 Topic 可以有各自的 Sandbox，让多人讨论中的文件与个人工作分开保存。执行代码时，Agent 在对应环境里运行命令和安装工具，也能读写文件。

这里需要区分文件保存和机器在线。CubePlex 的 Sandbox 可以暂停或关闭，工作文件仍保留在持久存储中。下次需要运行代码时，容器启动或恢复后继续使用这些文件。CubePlex 在这里保证的是工作文件的延续。Manus Cloud Computer 除了保留文件和软件环境，还强调程序全天候在线。需要托管常驻服务时，仍要单独考虑实例的暂停与回收，以及服务可用性。

团队还需要复用 Agent 已经掌握的工作方式。文件可以保存下来，角色设定和业务知识也应当有明确的管理位置，工具授权同样如此。

在 CubePlex 中，这些配置围绕 Workspace 组织。成员使用同一套 Agent Persona 和启用的 Skills，Workspace Memory 保存共享的项目事实和流程。成员从 Web 或 IM 入口发起不同任务时，继续使用这些配置，无需为每段新对话重新准备一个 Agent。

共享工具也有授权范围。MCP 连接器在 Workspace 中启用，凭据可以属于组织、Workspace 或某位成员。同一个连接器可以使用团队的服务账号，也可以要求每位成员连接自己的账号。共享 Agent 的工具配置时，个人身份仍能分别管理。

团队因此可以在 CubePlex 中持续维护一个 Workspace Agent，让它使用已经配置的知识和工具处理新任务。个人工作和协作任务使用各自的 Sandbox，文件在相应范围内保留。关闭一次对话以后，团队仍然能继续使用这个 Agent，也能找到此前工作留下的文件。
